# 用户端取消预约

```http
POST /user/reservations/1001/cancel
authorization: <用户登录返回的 token>
```

`1001` 是预约订单 ID，不是时段 ID；无需请求体或 `requestId`。
预约响应中的 `id` 是字符串（雪花 ID），前端应原样拼入路径，不要转换成 JavaScript Number。
成功返回 `code=1`，`data` 为订单详情，`data.status` 为 `CANCELLED`。
用户主动取消时，`data.failureReason` 记录“用户主动取消预约”。

| 当前订单状态 | 处理方式 |
| --- | --- |
| `SUCCESS` | 时段尚未开始时允许取消，释放一个已占用名额 |
| `PROCESSING` | 时段尚未开始时允许取消，不释放名额，因为尚未占用 |
| `CANCELLED` | 直接返回现有订单，不重复释放名额，不覆盖原取消原因；时段开始后重试也成功 |
| `FAILED` | 返回 409，订单保持失败状态 |

未登录或 token 失效返回 401；订单 ID 非正数返回 400。
订单不存在或不属于当前用户时均返回 404。
有效预约的时段已开始（含已结束）时返回 409。
时段关闭不妨碍取消尚未开始的预约；取消个人订单不会关闭时段，也不影响其他用户的订单。
用户主动取消不创建管理员取消邮件任务，不发送邮件。

取消在同一个数据库事务内按“时段行锁 → 订单行锁”处理，拿到锁后读取最新订单状态。
与消息消费、管理员取消采用一致的顺序：消费者先完成，则取消成功订单并释放名额；
用户先取消，则消费者及迟到的重复消息看到 `CANCELLED` 后直接结束。
订单状态更新或名额释放失败时整体回滚；并发重复取消只释放一次名额。

重新预约需使用新的 `requestId`；旧 `requestId` 仍对应原来的已取消订单。
重新预约仍受时段开放状态、开始时间、剩余名额等校验约束。

```powershell
$env:JAVA_HOME = 'D:\develop\JDK-17'
mvn -o '-Dtest=AdminManagementTest,ReservationConsumeTest,ReservationSubmitFlowTest' test
```

测试使用真实 MVC 拦截器、Service、MyBatis 和 H2 事务，模拟 Redis/Redisson 及邮件边界。
覆盖登录、归属、参数、状态与时间限制、重复取消、名额隔离、事务回滚，
以及用户取消与消费者、管理员取消的两种并发执行顺序；不连接业务数据库或发送真实邮件。
